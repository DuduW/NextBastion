# PRD：角色管理改造（用户组管理下线）

> 版本 v1.0 · 2026-10-16 · 状态：**待决策**（先审查后实施）
> 需求来源：吴大宝 2026-10-16 16:37

---

## 0. 需求原文

1. 取消用户组管理
2. 改用户组管理 为角色管理
3. OpenLDAP 同步的时候 选择对应角色组

## 1. 现状（As-Is）

| 项 | 现状 |
|----|------|
| 角色模型 | 硬编码 3 角色：`admin` / `auditor` / `user`（DB `users.role` 字符串列，无表） |
| 用户组管理页 | `user_groups` 表 + `user_group_map`（用户↔组多对多）+ 侧边栏「用户组管理」页 |
| 组的用途 | ① 授权策略可按组批量授权（`access_policies.user_or_group_type='group'`）② 用户列表显示所属组 |
| LDAP 角色 | 同步时按 `memberOf` 匹配配置的 DN 映射（bastion-admins → admin 等），**已有**「角色组映射」配置 |
| LDAP 组 | `_resolve_group_ids` 把 memberOf 映射到本地用户组（组成员自动维护） |

## 2. 方案（To-Be）

### 2.1 核心决策点（需你拍板）

**决策 A：用户组下线后，"按组批量授权" 怎么办？**

| 选项 | 说明 | 影响 |
|------|------|------|
| **A1（推荐）** | 按组授权能力**保留**，但组的来源只剩 LDAP 同步（本地手工组页面下线）；授权页仍可选"用户组" | 损失：本地建组能力。保留：LDAP 组授权（企业场景主流） |
| **A2** | 彻底删除组授权——策略只支持按用户授权 | 授权管理简化；有 100+ 用户的企业会痛苦（逐个授权） |
| **A3** | 组概念保留但改名"角色组"，与 RBAC 角色打通（见决策 B） | 改动最大，语义要重新梳理 |

**决策 B：「角色管理」页的范围？**

| 选项 | 说明 |
|------|------|
| **B1（推荐）** | 静态展示 3 个系统角色（admin/auditor/user）的**权限矩阵**（可访问页面、可执行操作、数据范围），不可增删角色；提供「默认角色」设置（新建用户/LDAP 同步未匹配时的兜底角色）+ 批量改用户角色入口 | 轻量，信息价值高 |
| **B2** | 完整自定义角色（角色表 + 权限点表 + 编辑器） | 重；当前 3 角色模型是产品定位，短期不建议 |

**决策 C：LDAP「选择对应角色组」交互？**

| 选项 | 说明 |
|------|------|
| **C1（推荐）** | 现有 LDAP 设置里的角色 DN 映射（bastion-admins → admin）**迁入角色管理页**，做成可视化映射卡片：左侧角色（3 个固定）→ 右侧 LDAP 组 DN（多选/搜索）；同步时按映射解析角色 | 配置集中，所见即所得 |
| **C2** | 保持现状（在系统设置 → LDAP 里配 DN），角色管理页只读展示映射结果 | 改动最小 |

### 2.2 推荐组合：A1 + B1 + C1

### 2.3 功能清单（按推荐组合）

| # | 功能 | 说明 |
|---|------|------|
| F1 | 侧边栏「用户组管理」移除 | 页面下线；`user_groups`/`user_group_map` 表保留（LDAP 组同步仍写入，授权用） |
| F2 | 新页「角色管理」（侧边栏替换原位置） | 三块布局：① 角色卡片（3 个，含权限矩阵说明）② 默认角色设置 ③ LDAP 角色组映射编辑 |
| F3 | 角色权限矩阵（只读展示） | 每角色列出：可访问页面（仪表盘/我的资产/…）、关键能力（审计回放/授权管理/系统设置…）——对齐现有 PAGE_ROLES + require_role 实际逻辑 |
| F4 | 默认角色设置 | 下拉选择；新建用户表单与 LDAP 同步未命中映射时使用（当前硬编码 user） |
| F5 | LDAP 角色组映射可视化 | 3 张映射卡：角色 ← LDAP 组 DN 列表（可添加多 DN、实时测试连接拉组列表供选择）；保存后同步立即生效 |
| F6 | 批量改角色 | 角色卡片上「查看该角色用户」→ 勾选批量切换角色（复用资产管理批量条交互） |
| F7 | LDAP 同步逻辑对齐 | `_resolve_role` 读取新映射存储（与 C1 同源）；未命中 → 默认角色（F4） |

### 2.4 不做的事（Out of Scope）

- 不引入自定义角色/细粒度权限点（B2 方向）
- 不删除组授权数据模型（保留 A1 的能力）
- 不动 RDP/SFTP/审计等既有功能

## 4. 数据与接口设计（推荐组合下）

```
表：
  role_settings（新增，单行）: default_role VARCHAR(16) DEFAULT 'user'
  ldap 角色映射：沿用 settings 存储（key=ldap_config，detail.role_map={admin:[dn...],auditor:[dn...]}）
  user_groups / user_group_map：保留不动（LDAP 组同步 + 组授权）

接口：
  GET/PUT /api/v1/role-settings          （default_role 读写）
  GET    /api/v1/role-matrix             （3 角色权限矩阵，服务端聚合 PAGE_ROLES 对应关系）
  GET/PUT /api/v1/settings/ldap/role-map （映射读写；并入现有 ldap 配置亦可）
  POST   /api/v1/users/batch-role        （批量改角色 [{id, role}]）
  GET    /api/v1/ldap/groups             （测试连接拉取组 DN 列表，供映射选择）
```

## 5. 迁移与兼容

| 项 | 处理 |
|----|------|
| 现有 6 个本地用户组 + 成员映射 | 保留数据；授权管理页仍可选组（数据不丢） |
| 组管理页历史操作 | 审计已有记录，无需迁移 |
| LDAP 配置中的旧角色 DN 字段（map_admin/map_auditor） | 读取时自动转换为新 role_map 格式（向后兼容） |
| 前端路由 `#groups` | 移除导航入口；直接访问跳转角色管理 |

## 6. 验收标准

1. 侧边栏无「用户组管理」，有「角色管理」；groups 路由重定向
2. 角色管理页展示 3 角色卡 + 权限矩阵（与实际 PAGE_ROLES/require_role 一致）
3. 默认角色设置生效：新建用户/LDAP 未命中用户落默认角色
4. LDAP 映射卡可视化编辑并保存；立即同步后新用户角色按映射落库
5. 批量改角色可用（勾选→切换→审计记录 role_change）
6. 组授权不受影响（授权管理仍可选用户组=LDAP 同步的组）
7. 回归 57/57 + 新增用例（角色设置/映射/批量）全绿
