# NextBastion 角色权限矩阵（PRD §2 落地设计）

> 版本 v1.0 · 2026-10-12 · 随 RBAC 实现同步更新

## 1. 角色定义（users.role）

| 角色 | 值 | 对应 PRD 角色 | 定位 |
|------|-----|--------------|------|
| 系统管理员 | `admin` | 系统管理员 | 全功能：用户/资产/授权/审计/强断 |
| 安全审计员 | `auditor` | 安全审计员 | 审计中心只读 + 会话强断；**无**任何配置写权限 |
| 运维用户 | `user` | 普通运维用户 | 本人资产连接、本人会话/命令查看 |
| 第三方/临时 | `user`（配合临时授权策略） | 第三方外包 | 用「用户级 + valid_until 策略」表达，非独立角色 |

## 3. 前端导航矩阵（侧边栏显隐）

| 菜单 | admin | auditor | user |
|------|:----:|:-------:|:----:|
| 仪表盘 / 我的资产 | ✓ | ✓ | ✓ |
| 资产管理 / 授权管理 / 用户管理 | ✓ | ✕ | ✕ |
| 在线会话 / 会话审计 / 命令审计 | ✓ | ✓ | ✕ |

## 4. 设计要点

1. **auditor 是新增角色值**：只读审计 + 强断（应急权），杜绝「既管配置又管审计」的自审自弊。
2. **第三方临时用户不设独立角色**：PRD 语义为「临时授权」，用 user 角色 + 单用户策略 + valid_until 表达，到期自动失效，避免角色爆炸。
3. 后端为权威：require_role 扩展多角色；前端显隐仅是体验优化。
4. 用户表单角色下拉：系统管理员/运维用户/安全审计员三选。
