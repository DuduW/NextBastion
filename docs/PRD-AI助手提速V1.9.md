# PRD：AI 助手提速（对标业界 · V1.9）

> 版本 v1.0 · 2026-10-19 · 状态：**已批准执行**（用户：及时性最重要）
> 依据：业界 LLM 延迟优化实践（TTFT 优先/缓存/模型路由/UX 感知）× 当前链路实测数据

## 1. 现状与业界对比

| 指标 | 业界标准 | 我们现状 | 差距 |
|------|---------|---------|------|
| 首字延迟 TTFT | 交互式 chat p95 < **1.5s** | low ≈0.9s ✅ / high 3-25s | high 模式超标 |
| 总响应 | <4-10s | low 9-13s（长答案） | 输出速度受模型限制 |
| 重复问题 | 缓存命中 **<100ms** | 每次全量调用 LLM | 🔴 无缓存 |
| 感知体验 | 打字指示/乐观 UI | "分析中…"固定文案 | 可提升 |
| 连接复用 | keep-alive 连接池 | urllib 每次新建 TCP+TLS | 每次 +200-400ms |

**业界核心打法**（本次全采纳）：①响应缓存（高频问题秒回）②提示词精简（短输入=快 TTFT）③连接复用 ④输出限长 ⑤轻量模型路由 ⑥取消传播（用户关面板即停止生成）⑦打字光标动效。

## 2. 改动清单

| # | 改动 | 预期收益 | 层 |
|---|------|---------|-----|
| P1 | **语义缓存**：问题+场景归一化哈希 → 完整答案缓存（内存 LRU 200 条 + command_logs 级 TTL 24h），命中直接回放（分块 yield 模拟流式） | 重复问题 **<100ms**（尤其快捷按钮高频点击） | 后端 |
| P2 | **HTTP 连接复用**：urllib → http.client HTTPSConnection 池（按 base_url 保持长连接），省每次 TCP+TLS 握手 | TTFT -200~400ms | 后端 |
| P3 | **系统提示词瘦身**：五场景提示词压缩至 2 行内（去除解释性文字）；快捷按钮问题模板精简 | 输入 token 减半 → TTFT 降低 | 后端 |
| P4 | **快捷按钮默认 low + 精简输出**：快捷动作请求加 `max_tokens=800`（直答场景够用）；提示词要求"答案≤300字优先" | 总时长 -30% | 后端 |
| P5 | **取消传播**：面板收起/关闭页签时 abort fetch → 服务端感知断连即断上游 LLM 流（uvicorn 断连异常传播） | 不浪费模型算力；用户改问更快 | 前后端 |
| P6 | **打字动效升级**：等待首字期间显示三点跳动动画（而非静止"分析中"），首字到达即替换 | 感知等待缩短 | 前端 |
| P7 | **LLM 延迟埋点**：command_logs 审计记录 TTFT/总时长/缓存命中——上线后可持续观测（SLO：low p95<1.5s） | 可运营 | 后端 |

**不做**（明确排除）：换更小模型（质量损失）、边缘部署（内网无此诉求）、答案预计算（场景太发散）。

## 3. 验收标准

1. 同一快捷按钮问题第二次点击：**首字 <300ms**（缓存命中）
2. 缓存命中时面板完整显示答案（分块流式效果保留）
3. low 模式新问题首字 p95 <1.5s（10 次采样）
4. 收起面板后服务端日志显示上游流被中断（连接断开传播）
5. 打字动画在等待期可见、首字后消失
6. 审计行含 `ttft_ms/duration_ms/cached` 字段
7. 全量回归 58/58 + AI E2E 12/12
